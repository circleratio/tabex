# tabex 実装計画

この計画は `doc/spec.md` に書いた設計を、実装の手順に分けたものである。各ステップには「やること」と「完了条件」を書いた。完了条件を満たしてから次のステップに進む。

## 前提となる開発環境

- Rust stable（`x86_64-pc-windows-msvc`）。確認時点のバージョンは cargo 1.99.0。
- Visual Studio Build Tools 2022（VC ツール一式）
- 注意: cargo は `%USERPROFILE%\.cargo\bin` にインストールされているが、シェルによってはこのフォルダが PATH に入っていない。その場合は PATH に追加するか、`cargo.exe` をフルパスで実行する。
- 注意: キー割り当てツール（Alt の組み合わせを横取りするもの）が動いている環境では、Alt+英字によるメニュー操作を自動テストできない。その場合はメニューをマウスで操作して確かめる。

## 依存関係の全体像

```
S1 雛形 ─┬─ S2 model ──┬─ S3 store ────────────────┐
         │             │                            │
         ├─ S4 cli/instance                         │
         │             │                            │
         └─ S5 fs ─────┴─ S6 UI骨格（ウィンドウ/レイアウト/ListView）
                                 │
                                 ├─ S7 タブバー・アドレスバー・ナビツリー
                                 ├─ S8 ワークスペース統合（S3 + S6）
                                 ├─ S9 シェル統合: アイコン/右クリック
                                 └─ S10 ファイル操作/クリップボード/D&D/Undo
                                          │
                       S11 性能チューニング ─ S12 手動動作確認 ─ S13 最終確認
```

- S2・S4・S5 は S1 さえ終われば、互いに並行して進められる。S3 は S2 のあとに進める。
- S6 は S2 と S5 の完成を前提とする。
- S7・S9・S10 は S6 が終われば並行して進められる。S8 だけは S3 と S6 の両方が終わってから始める。
- S11 以降は、それより前の全ステップが完了してから行う。

## S1. プロジェクトの雛形

**やること**
- `cargo init --name tabex` でプロジェクトを作り、`Cargo.toml` を設計書 §10 のとおりに書く。依存クレートは、その時点の最新の安定版を確認して記入する。
- 次のファイルを用意する。
  - `.cargo/config.toml`（CRT を静的リンクする `+crt-static` の指定）
  - `res/tabex.manifest`
  - `res/tabex.rc`
  - `res/tabex.ico`（仮のアイコンでよい）
  - `build.rs`（マニフェスト・アイコン・バージョン情報を exe に埋め込む）
- 設計書 §2 のモジュール構成に沿って、空のモジュールを作る。
- `main.rs` は、空のウィンドウを 1 つ表示して閉じれば終了するだけのものにする。

**完了条件**
- `cargo build --release` が警告なしで成功する。
- 作った exe を実行するとウィンドウが表示され、閉じると終了する。
- exe のプロパティ画面の「詳細」タブに、バージョン 0.1.0 が表示される。
- `dumpbin /dependents` で見たとき、依存先が OS の DLL だけである（vcruntime の DLL に依存していない）。

## S2. データモデル（`model`）

**やること**
- 次のモジュールを実装する。いずれも Win32 API を呼ばない純粋なロジックとする。
  - `workspace`: ワークスペース・ペイン・タブ・表示状態の型
  - `tabs`: タブを開く・閉じる・移動・複製・再オープンする操作
  - `history`: 戻る / 進むの履歴
  - `listing`: 一覧データ。チャンクのマージ、差分の反映、絞り込み、選択状態の管理を含む
  - `layout`: 各部品の配置計算
  - `command`: `Command` 列挙型
- 設計書 §11.1 の表で、`model::*` にあたる単体テストを書く。

**完了条件**
- `cargo test model::` が全件成功する。
- 「チャンクに分けてマージした結果」と「全件を一度にソートした結果」が一致することを、性質ベースのテストで確かめる。乱数で 1,000 通りのケースを作る（外部クレートは使わず、簡単な線形合同法で乱数を作る）。

## S3. 永続化（`store`）

**やること**
- 次のモジュールを実装する。
  - `paths`: 保存先の解決（`TABEX_HOME` があればそれを使う）、ワークスペース名のチェック
  - `workspace_file`: TOML とデータモデルの相互変換（DTO 経由）、version のチェック、項目が欠けているときの既定値
  - `config`: `config.toml` の読み書き
  - `autosave`: 自動保存のタイミング判定（Debouncer）と、途中で壊れない書き込み
- 単体テストと、結合テスト `tests/store.rs` を書く。

**完了条件**
- `cargo test store::` と `cargo test --test store` が全件成功する。
- 要求仕様 `doc/requirement.md` に載っている `dev.toml` の例をそのまま読み込める。それを保存し直して再び読み込んでも、データモデルとして同じ内容になる。

## S4. コマンドライン解析と単一インスタンス（`cli`, `instance`）

**やること**
- `cli::parse` を実装し、引数が不正なときのメッセージを決める。
- メッセージの出し方を実装する。起動元のコンソールに表示できればそこに出し（`AttachConsole`）、できなければ `MessageBoxW` で表示する。
- 単一インスタンスの仕組みを実装する。名前付き mutex で起動済みかどうかを判定し、起動済みなら `WM_COPYDATA` で引数を送り、起動中のウィンドウを前面に出す。
- S1 で作った空ウィンドウを使い、引数を受け取ったらその内容をタイトルバーに表示するようにして、仕組みが動くかを確かめる。

**完了条件**
- `cargo test cli::` が全件成功する。
- コマンドプロンプトで `tabex.exe --version` を実行すると `tabex 0.1.0` と表示され、終了コードが 0 になる。
- `tabex.exe --bogus` を実行するとエラーメッセージが出て、終了コードが 2 になる。
- tabex を起動した状態でもう一度 `tabex.exe C:\Windows` を実行すると、起動中のウィンドウのタイトルに引数が表示され、2 回目のプロセスは終了コード 0 で終わる。

## S5. ファイルシステム（`fs`）

**やること**
- `enumerate` を実装する。
  - 通常のフォルダは `FindFirstFileExW` で高速に列挙する。
  - 特殊フォルダは `IShellFolder` で列挙する。
  - 結果をチャンクに分けて送る仕組み（最初は 1,000 件、以降は 50ms ごと）と、古くなった列挙を途中で止める仕組みを作る。
  - 長いパスを扱えるように、必要に応じて `\\?\` を付けて API に渡す。
- `sort` を実装する。比較には `CompareStringEx`（`SORT_DIGITSASNUMBERS`）を使い、フォルダを先に並べる。
- `watch` を実装する。`ReadDirectoryChangesW` で変更を受け取り、100ms ためてから通知する。
- 列挙・ソート・監視を担当するワーカースレッドと、UI へ結果を知らせる仕組み（`app::worker`）を作る。
- 結合テスト `tests/enumerate.rs` と `tests/watch.rs` を書く。
- 性能測定用の `examples/enum_bench.rs` を書く。

**完了条件**
- `cargo test fs::`、`cargo test --test enumerate`、`cargo test --test watch` が全件成功する。
- `cargo run --release --example enum_bench -- %TEMP%\tabex_bench --create 100000` を実行して、次の 2 つを満たす。
  - 最初のチャンクが 50ms 以内に届く。
  - 全件そろうまでの時間を測って記録する（目安は 1 秒以内）。

## S6. UI の骨格

**やること**
- メインウィンドウを作る。
  - 高 DPI 対応（Per-Monitor V2）と、`WM_DPICHANGED` を受けたときの再レイアウト
  - `model::layout` で計算した位置に各部品を配置する
  - 左右 2 ペインを並べ、境界をドラッグして幅を変えられるようにする
  - ステータスバー
- ファイル一覧（`ui::listview`）を作る。
  - 仮想モード（`LVS_OWNERDATA`）を使う
  - 詳細 / 一覧 / アイコンの各表示モード
  - 列見出しをクリックしたときのソート
  - 列の幅と順番の変更
- `App` 構造体を作り、`Command` を受け取って実行するようにする。
- キー操作を `Command` に変換する仕組み（`ui::accel`）を作り、設計書 §7.7 の既定のキー割り当てを入れる。
- この時点のタブは、各ペインに固定で 1 つずつとする。
- 起動時の引数として受け取ったパスを開けるようにする。
- フォルダの移動（ダブルクリックで入る、Backspace で上へ）と、戻る / 進むを実装する。

**完了条件**
- `C:\Windows\System32` を開くと一覧が表示され、スクロールしても引っかからない。
- S5 で作った 10 万件のフォルダを開いても、ウィンドウが応答しなくなる時間がない。
- 列見出しをクリックするとソート順が切り替わり、名前が自然順（`file2` が `file10` より前）で並ぶ。
- Tab キーで、操作対象のペインが左右に切り替わる。
- DPI の違うモニターにウィンドウを移しても、文字やアイコンがぼやけず、レイアウトも崩れない。

## S7. タブバー・アドレスバー・ナビゲーションツリー

**やること**
- タブバー（`ui::tabbar`）を作る。
  - GDI でダブルバッファリングして描画する
  - タブの幅を自動で詰め、収まらないときはスクロールボタンを出す
  - クリック / 中クリック / ダブルクリック / ドラッグでの並べ替え / 反対側のペインへの移動
  - 右クリックメニュー
- タブ関連の `Command` を実装する: NewTab / CloseTab / ReopenClosedTab / NextTab / PrevTab / SelectTab / DuplicateTab
- 一覧データを保持するタブを最大 4 つに絞る LRU を実装する。
- アドレスバー（`ui::addressbar`）を作る。
  - パンくず表示と、区切りクリックで出るサブフォルダ一覧
  - パスの直接入力（`SHAutoComplete` で入力補完）
  - 入力したパスを解決できないときのエラー表示
- ナビゲーションツリー（`ui::navtree`）を作る。
  - ウィンドウ表示後のアイドル時に作り始める
  - ノードを展開したときに、子の項目を非同期で読み込む
- フォルダが見つからないタブの表示を作る（「再試行」と「親フォルダへ」のボタン付き）。

**完了条件**
- 要求仕様 §4 のタブ操作がすべて、マウスとショートカットの両方で行える。
- タブを 20 個開いた状態で、メモリ使用量が 50MB 以下に収まっている。
- アドレスバーに `shell:RecycleBinFolder` を入力して Enter を押すと、ごみ箱の中身が表示される。

## S8. ワークスペースの統合

**やること**
- 起動時と切替時の処理（設計書 §4.5）を実装する。
- 自動保存をつなぎ込む。
  - 次の変更が起きたら dirty フラグを立てる: タブの開閉・移動、フォルダの移動、表示状態の変更、ペインの分割比率の変更
  - 最後の変更から 1 秒たったら保存する（`SetTimer`）
  - ワークスペースの切替時、ウィンドウを閉じるとき、Windows の終了時は、待たずにすぐ保存する
- ワークスペース一覧のポップアップ（`ui::workspace_dialog`）と、メニューバーの「ワークスペース」メニューを作る。
- 新規作成 / 名前を付けて保存 / 名前の変更 / 削除 / 切り替え の各 `Command` を実装する。
- `--workspace` の引数を処理する。起動時に指定された場合と、起動中のインスタンスに転送されてきた場合の両方に対応する。
- 読み込めないワークスペースファイルへの対処（設計書 §4.5 の 3）を実装する。
  - エラーを通知する
  - `untitled` という名前で新しいワークスペースを作る
  - 壊れたファイルを自動保存で上書きしない

**完了条件**
- 要求仕様の「ワークスペースを使う流れ」の手順 1〜5 が、そのとおりに動く。
- 保存されたファイルの内容が、要求仕様にあるファイル例と同じ構造になっている。
- 保存してあるフォルダを削除してから起動すると、そのタブだけが「フォルダが見つかりません」の表示になり、ほかのタブは普通に復元される。
- ワークスペースファイルを壊してから（TOML として読めない内容にしてから）起動すると、エラーが通知されて起動は続く。壊したファイルは書き換えられていない。

## S9. シェル統合: アイコン・右クリックメニュー・プロパティ

**やること**
- システムイメージリストを ListView に設定し、アイコンを表示する。
  - まず拡張子だけから決まるアイコンを即座に表示する
  - `.exe` などの本来のアイコンは icon ワーカーで取得し、画面に見えている行だけ差し替える
- アイコン表示（大・中）のときにサムネイルを表示し、LRU キャッシュに保存する。
- 種類の列に表示する名前を、拡張子ごとにキャッシュする。
- 右クリックメニューを実装する。
  - 項目を右クリックしたとき用と、何もない所を右クリックしたとき用の 2 種類
  - `IContextMenu3` へのメッセージ転送
  - リネーム・削除など一部の動詞は、シェルに任せず tabex の `Command` として実行する
- プロパティ画面（Alt+Enter）を開けるようにする。

**完了条件**
- 右クリックメニューに、他のアプリが追加した項目（7-Zip や VS Code などが入っていればその項目）が、アイコン付きで表示され、選ぶと実行できる。
- 写真が入ったフォルダをアイコン（大）表示にすると、サムネイルが表示される。
- 特殊フォルダ（PC、ごみ箱）でも右クリックメニューが表示される。

## S10. ファイル操作・クリップボード・D&D・元に戻す

**やること**
- `IFileOperation` を実行するワーカーを作る。
  - 処理の進み具合を受け取る仕組み（`IFileOperationProgressSink`）を実装し、実際に行われた操作を元に戻す操作用に記録する（`UndoRecord`）
- 次の操作を実装する: コピー / 切り取り / 貼り付け、削除（ごみ箱へ / 完全に削除）、その場リネーム（拡張子の手前まで選択して始める）、新しいフォルダの作成。
- エクスプローラとの間でもクリップボードをやり取りできるようにする（`Preferred DropEffect` などの形式に対応する）。
- ドラッグ＆ドロップを実装する。
  - ドロップを受ける場所: ListView・タブバー・ナビゲーションツリー（`IDropTarget`）
  - ドラッグの開始（`SHDoDragDrop`）
  - ファイルをドラッグしたままタブの上で 500ms 止まると、そのタブに切り替える
- 元に戻す操作（Ctrl+Z）を、自前の操作履歴（最大 50 件）で実装する。

**完了条件**
- tabex でコピーしてエクスプローラに貼り付けられ、逆にエクスプローラでコピーして tabex に貼り付けられる。切り取りでも同じことができる。
- tabex とエクスプローラの間で、ドラッグ＆ドロップによるコピーと移動ができる。
- 設計書 §6.3 の表にある 5 種類の操作が、それぞれ Ctrl+Z で元に戻る。
- 日本語の名前を、IME を使って入力しながらその場でリネームできる。

## S11. 性能チューニング

**やること**
- `TABEX_TRACE=1` を設定したときに、起動の各段階にかかった時間を記録する仕組みを実装する。
- 要求仕様 §2 の性能目標を計測し、満たしていない項目があれば改善する。
- 改善するときは、まず計測で遅い箇所を特定する。改善策の候補は次のとおり。
  - 起動時に必ずしも必要でない処理を、ウィンドウ表示後に遅らせる
  - 不要なメモリ確保をなくす
  - 一覧データを保持するタブの数（LRU の上限）を調整する
- パニックしたときのクラッシュログ出力を実装する。

**完了条件**
次の数値を計測して記録し、すべて目標を満たしている。
- 起動時間（コールドスタート、タブ 6 個のワークスペースを復元する場合）: 300ms 以内
- 待機時のメモリ使用量: 50MB 以下
- 10 万件のフォルダを開いたとき: UI が固まらない
- exe のサイズ: 3MB 以下

## S12. 手動動作確認

コマンドプロンプトで、次の手順を上から順に実行する。tabex は GUI アプリなので、`start /wait` を付けて終了を待たないと終了コードを確認できない。`%TABEX_HOME%` を一時ディレクトリに向けておけば、普段の設定を汚さずに確認できる。

```bat
set TABEX_HOME=%TEMP%\tabex_check
rmdir /s /q %TABEX_HOME%

rem --- CLI ---
start /wait "" target\release\tabex.exe --version
echo exit=%ERRORLEVEL%
rem 期待: "tabex 0.1.0" / exit=0
start /wait "" target\release\tabex.exe --help
echo exit=%ERRORLEVEL%
rem 期待: 使いかたが表示される / exit=0
start /wait "" target\release\tabex.exe --bogus
echo exit=%ERRORLEVEL%
rem 期待: エラーメッセージ / exit=2
start /wait "" target\release\tabex.exe C:\no\such\dir
echo exit=%ERRORLEVEL%
rem 期待: エラーメッセージ / exit=2
start /wait "" target\release\tabex.exe --workspace nosuch
echo exit=%ERRORLEVEL%
rem 期待: エラーメッセージ / exit=2

rem --- 初回起動 ---
start target\release\tabex.exe
rem 期待: 左にユーザーフォルダ、右にダウンロードが表示される。%TABEX_HOME%\workspaces\default.toml ができる

rem --- 単一インスタンス ---
start /wait "" target\release\tabex.exe C:\Windows
echo exit=%ERRORLEVEL%
rem 期待: 起動中のウィンドウのアクティブペインに C:\Windows のタブが追加される / exit=0
```

続いて、GUI を操作して次の項目を確かめる。

1. **ワークスペースを使う流れ**: 要求仕様の手順 1〜5 を実際に行う。`dev.toml` の内容が要求仕様の例と同じ構造になっていることを確かめる。
2. **フォルダが見つからない場合**: `dev` に `%TEMP%\tabex_gone` を開いたタブを足す。tabex を終了してからそのフォルダを削除し、再び起動する。そのタブだけが「フォルダが見つかりません」の表示になることを確かめる。
3. **壊れたファイル**: `photo.toml` の中身を `xxx` に書き換えてから、`--workspace photo` を付けて起動する。エラーが表示され、`photo.toml` は書き換えられないことを確かめる。
4. **タブ操作**: 要求仕様 §4 の各操作を、マウスとショートカットの両方で行う。
5. **ファイル操作**: コピー・移動・削除・リネーム・新しいフォルダの作成を行い、それぞれ Ctrl+Z で元に戻ることを確かめる。エクスプローラとの間でクリップボードとドラッグ＆ドロップが使えることも確かめる。
6. **シェル統合**: 右クリックメニュー（項目の上と何もない所の両方）、アイコン、サムネイル、プロパティ画面、特殊フォルダ（PC・ごみ箱・ネットワーク）、UNC パス。
7. **表示**: 表示モードの切り替え、ソート、列の追加・削除と幅の変更を行い、ワークスペースを切り替えて戻しても状態が保たれていることを確かめる。隠しファイルと拡張子の表示切り替えも確かめる。

5. キー割り当てページ: 「ホーム」に Ctrl+Shift+H を割り当てようとすると「ドットファイル」に割り当て済みの確認が出て、「はい」で移る。適用すると Ctrl+Shift+H でホームへ移動し、変えたコマンドのキーの列が太字になる。「既定に戻す」「すべて既定に戻す」で戻る。入力欄で Alt+F や Ctrl+Tab を押すと、そのキーが入力される。修飾キーなしの Tab・Esc・Enter はダイアログの操作になる。`config.toml` の `[keys]` には既定との違いだけが書かれる。
6. その他ページ: シェルに `cmd.exe /k echo tabex` を入れて適用すると、`:sh` でそのコマンドが開く（確認後にウィンドウを閉じる）。migemo のチェックを外して適用すると、`/` での絞り込みに `migemo` の表示が出なくなる（`rustmigemo.dll` を置いた環境で確認する）。
7. 外での編集: tabex を起動したまま `config.toml` をメモ帳で開き、`show_hidden = true` に書き換えて保存すると、隠しファイルがすぐ表示され、ツールバーのボタンも押し込まれる。`[[homes]]` を書き足して保存すると、ホームボタンの一覧に出る。書き間違えて保存すると「設定ファイルを読み込めませんでした: ...」が出て、それまでの設定のまま動く。
8. 外で編集してから（読み直しのあとで）tabex を終了しても、編集した内容が `config.toml` に残っている。
9. ダイアログを開いたまま外で `config.toml` を書き換え、キャンセルで閉じると外の変更が反映される。同じ状況で OK で閉じると、ダイアログの内容が残る。
- 作業用の一時フォルダを削除する。
